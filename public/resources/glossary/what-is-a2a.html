Definition & overview

Agent2Agent is an open protocol for communication and collaboration between independent AI agent systems. It supports capability discovery and task exchanges without requiring agents to share their internal implementation.

Analogy & mental model

It is a shared handover language for assistants working in different organisations.

Verify identity, task ownership and what information can cross an organisational boundary.

Why Agent2Agent (A2A) matters

Companies may use agents built by different providers. A shared task interface can reduce custom integration work, but it also creates new boundaries for identity and data sharing. Collaboration is only safe when ownership, permissions and completion criteria are clear.

Practical business example

A research assistant requests a permitted summary from another specialist agent without obtaining that agent’s private prompts or underlying customer documents.

Illustrative scenario, not a client case study or promised result.

How Agent2Agent (A2A) works

  1. An agent discovers another agent’s declared capabilities through its published interface.
  2. It sends an authorised task or message and receives status updates or requests for more input.
  3. It receives the resulting artifact or task outcome and checks whether it meets the original requirements.

Core components & mechanisms

  • Capability description
  • Tasks and status
  • Messages and artifacts

Protocol compatibility is not permission to disclose confidential information or execute unrestricted tasks.

Agent2Agent (A2A) vs MCP

A2A supports agent-to-agent task exchanges. MCP supports AI applications connecting to tools and data. They operate at different integration boundaries and can coexist.
