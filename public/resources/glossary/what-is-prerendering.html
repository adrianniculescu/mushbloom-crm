What is Prerendering?

Definition & overview

Prerendering creates ready-to-read HTML before a request, often during a site build. Unlike request-time rendering, the content stays as generated until refreshed or rebuilt; freshness and route coverage need management.

Analogy & mental model

You print the handbook in advance rather than printing a new edition for each visitor.

Regenerate pages when source content changes and verify every intended public URL.

Why Prerendering matters

Stable reference content can be delivered as ready-made HTML without introducing a request-time server. That makes the definitions available to non-JavaScript readers. The trade-off is maintaining synchronisation so the generated edition does not become stale.

Practical business example

A glossary produces a complete HTML guide for each term and regenerates all of them after a factual correction, alongside its text reference.

Illustrative scenario, not a client case study or promised result.

How Prerendering works

  1. Generate HTML for every intended public reference URL from the same source content.
  2. Serve those files with the correct page text, metadata and links.
  3. Regenerate and validate the files whenever definitions or guide content change.

Core components & mechanisms

  • Build-time source
  • Static route output
  • Regeneration checks

Do not show crawlers a different claim from the one visitors see. Generated and interactive editions must agree.

Prerendering vs SSR

Prerendered files are prepared before requests. SSR renders at request time; both can provide initial HTML, but their freshness and infrastructure requirements differ.
