# What is Server-side rendering (SSR)?

Source: https://mushbloom.uk/resources/glossary/what-is-ssr.html

By Mushbloom. Published and updated: 2026-10-12.

## Definition & overview

Server-side rendering produces a page’s HTML on the server before it reaches the browser. It can make content available without client-side execution, but it does not by itself guarantee indexing, performance or accurate metadata.

## Analogy & mental model

The visitor receives the completed document instead of instructions for assembling it.

Inspect the actual HTTP response for the page’s text, links and metadata.

## Why it matters

Some crawlers and link-preview services do not execute browser scripts. Server-produced HTML can make a route’s actual text and metadata available immediately. That is an accessibility and delivery property, not evidence of stronger rankings by itself.

## Practical business example

A glossary guide returns its definition and canonical metadata directly in the response, so an assistant does not need to run a browser to read it.

Illustrative scenario, not a client case study or promised result.

## How it works

1. A server processes the request for a specific page.

2. It produces HTML containing the page’s meaningful content and metadata.

3. The browser may hydrate interactive controls while the initial content remains readable.

## Core components

- Request-time HTML

- Per-page content and head

- Optional client hydration

SSR introduces operational considerations and does not fix weak content, blocked access or incorrect canonicals automatically.

## Server-side rendering (SSR) vs Prerendering

SSR generates HTML at request time. Prerendering generates it earlier, commonly during a build, and requires regeneration when the source changes.
